02

Execution tasks

1. Pin the CLI contract with RED tests

exec/src/cli.rs · exec/src/lib_tests.rs · .github/workflows/fork-verify.yml
  1. Parse a real --agent adversary new-session command and reject blank values.
  2. Reject resume, fork, and review combinations before startup.
  3. Add an exact, pass-count-gated workflow family.
  4. Push the test-only diagnostic and prove failure through gh api; later amend it away.
Acceptance: The Actions step fails specifically because the CLI/validator is absent, with no vacuous zero-test success.

2. Add the headless CLI surface

exec/src/cli.rs · exec/src/lib.rs
  1. Add global --agent ROLE for the root exec command.
  2. Validate a nonblank role and incompatible subcommands before auth/cloud/network startup.
  3. Keep role parsing out of the exec crate.
Acceptance: Parser and compatibility tests pass without touching role-layer internals.

3. Expose a narrow core adapter

core/src/agent/mod.rs · core/src/agent/role.rs
  1. Build a real temporary role fixture and prove model, effort, and developer instructions apply.
  2. Call the existing resolver and role-layer code through one public adapter.
  3. Snapshot and restore only invocation-owned safety/process fields.
  4. Use independent mutation-sensitive assertions for role application and runtime restoration.
Acceptance: Role identity wins; approval, sandbox/permission, CWD, writable roots, executable paths, hook bypass, ephemeral mode, and PSP survive.

4. Integrate before session startup

exec/src/lib.rs · exec integration tests
  1. Apply the role after final exec config resolution and before login/session startup.
  2. Assert unknown roles and incompatible modes cause zero mocked Responses requests.
  3. Assert outbound model and developer instructions come from the role.
  4. Assert conflicting CLI model/effort cannot defeat a role that sets them.
Acceptance: A mocked end-to-end turn observes role identity and preserved invocation safety; invalid selection remains local.

5. Verify and declare the capability

fork-verify.yml · fork-manifest.json · manifest tests
  1. Declare the named headless role-selection capability in the fork manifest.
  2. Amend the RED commit with production code and push using --force-with-lease.
  3. Require terminal green for every focused and existing workflow family.
  4. Confirm clean diff, exact coauthor, no local target artifacts, and untouched user file.
Acceptance: The final workflow is terminal green and fork-manifest --capabilities reports the new surface.

6. Release, install, and live-test

GitHub release · bundle fork lock/update metadata
  1. Publish the next fork tag from the green commit and verify GitHub-served checksums.
  2. Install the Linux artifact through the hardened dry-run-first bundle path; never compile locally.
  3. Run a closed-stdin codex exec --agent adversary whoami probe and verify server-reported identity plus developer-instruction behavior.
  4. Close the tracking issue only after deployed evidence is available.
Acceptance: The installed binary selects a real role end to end, and an unknown role fails before network activity.
