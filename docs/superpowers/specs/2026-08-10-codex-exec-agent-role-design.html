Give headless Codex a real named agent identity

Jump: Decision · Contract · Architecture · Verification · Risks
Decision

Add codex exec --agent <ROLE>

Resolve the role from the registry already loaded from $CODEX_HOME/agents and apply it through the existing core role-layer machinery. Do not duplicate profiles through --profile or translate TOML into ad hoc overrides.

Command contract

codex exec --agent adversary -- "Review this claim" < /dev/null
ConcernRule
IdentityThe role owns model, reasoning effort, and developer instructions, matching native spawn semantics.
RuntimeHeadless approval, sandbox/permissions, CWD, writable roots, executable paths, hook-trust bypass, persistence, and PSP remain invocation-owned.
ErrorsUnknown or malformed roles fail before an API request.
Existing sessionsResume and fork retain their recorded role. Review remains its dedicated mode; all three reject --agent.

Architecture

  • Exec CLI: add one optional role name and validate new-session-only use.
  • Core boundary: expose a narrow exec adapter around the existing role resolver and layer application.
  • Precedence: role identity fields win; the adapter reapplies invocation-owned runtime state after the config-layer rebuild.
  • No duplicate parser: the exec crate never reads or interprets agent TOML.

Verification

  • CLI parser accepts a role and rejects an empty value.
  • A real temporary role changes model, effort, and developer instructions.
  • Headless runtime selections survive role application.
  • Unknown roles and incompatible subcommands fail before mocked network traffic.
  • GitHub Actions builds and exercises the exact test filters non-vacuously.

Risks and mitigations

RiskMitigation
Role rebuild drops danger-full-access or never-approve.Snapshot and assert every invocation-owned runtime field.
CLI and spawn role semantics diverge.Call the same core role-layer function and share role-application tests.
Resume silently changes identity.Reject the combination at argument validation.
